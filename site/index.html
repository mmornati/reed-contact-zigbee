Why build it

A contact sensor that pulls its weight.

Battery sensors report and go back to sleep. This one stays awake, relays your other Zigbee devices, and tells you when something's wrong instead of failing silently.

A Zigbee router, too

Mains powered, so it routes traffic for every Zigbee device nearby. Your garage, shed or gate finally gets solid coverage.

Fail-safe by design

Only a magnet in place reads closed. A cut wire, a loose connector or a dead sensor all show up as open, never as a false "all good".

Z2M & HA native

A standard IAS Zone contact. One tiny converter and it shows up as a door/window sensor in Home Assistant.

No WiFi, no cloud

No passwords, IPs or app accounts. It keeps working when your WiFi doesn't, and nothing leaves your house.

Put it anywhere

If a magnet can move, you can watch it.

The reed goes on the fixed part, the magnet on the moving part. The same firmware works for all of these.

How it works

From a magnet to an automation.

The reed closes when the magnet is near. The ESP32-C6 debounces it, reports it as a Zigbee IAS Zone, and re-sends it every 5 minutes so Home Assistant never holds a stale state.

📡Zigbee meshIAS Zone contact

Zigbee2MQTT

Twelve lines and you're paired.

The converter uses Zigbee2MQTT's own building blocks, and CI checks it against the same library Z2M runs. The model string is verified against the firmware source on every commit.

external_converters/reed_contact.mjs
import * as m from 'zigbee-herdsman-converters/lib/modernExtend';

export default {
    zigbeeModel: ['C6ReedContact'],
    model: 'C6ReedContact',
    vendor: 'DIY',
    description: 'Mains-powered reed contact sensor and Zigbee router (XIAO ESP32-C6)',
    // contact: true = magnet in front of the reed (closed), false = open
    extend: [m.iasZoneAlarm({zoneType: 'contact', zoneAttributes: ['alarm_1']})],
};

FAQ

Good questions.

Why Zigbee and not WiFi / ESPHome?

For a single contact, Zigbee wins: it joins the mesh your other sensors already use, needs no credentials, survives WiFi outages and, being mains powered, adds a router where you usually need one. The trade-off is firmware updates over USB instead of over WiFi, and a small Z2M converter. For a device you install once, that's a good deal.

Why the Arduino framework instead of ESP-IDF?

Both run the same Espressif Zigbee stack. Arduino gets this sensor done in ~200 readable lines, which is easier for everyone to fork. ESP-IDF pays off for custom clusters, battery tuning down to the µA, or a commercial product.

Can it run on a battery?

It can, but then it should become a sleepy end device and stop routing. Commercial battery sensors are cheaper for that. This project is for places where power is close by and a router is welcome.

How do I know it's working?
  • The LED blinks while searching for a network and turns off once joined.
  • Zigbee2MQTT shows it as a Router with contact flipping as you move the magnet.
  • The state is re-sent every 5 minutes, and Z2M availability flags it if it disappears.
Is it tested?

Every commit runs host unit tests for the debounce and heartbeat logic (including millis() rollover), builds with both PlatformIO and Arduino CLI, tests the converter against zigbee-herdsman-converters, and validates the Home Assistant package with Home Assistant's own config checker.
